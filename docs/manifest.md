# ml-манифест: прогнозирование оттока клиентов

## 1. предыстория

бизнес-заказчик (отдел маркетинга телеком-оператора) несёт убытки из-за высокого
оттока клиентов. текущий метод борьбы — реактивный: удержание клиента только после
того, как он подал заявление об уходе. это дорого и неэффективно. нужен проактивный
инструмент, который заранее выявляет клиентов с высоким риском оттока.

## 2. ценностное предложение

создание ml-сервиса, который ежедневно формирует список клиентов с высоким риском
оттока. это позволит маркетингу запускать превентивные кампании и снизить ежемесячный отток на 5% в течение квартала.

## 3. цели

- разработать и обучить модель бинарной классификации на исторических данных
- создать автоматический пайплайн для переобучения модели (еженедельно)
- разработать api для получения предсказаний
- внедрить мониторинг качества модели в проде
- реализовать механизм автоматического отката модели при падении качества ниже порога

## 4. решение

создаём ml-систему уровня 2 по классификации mlops.

**что входит:**
- оркестратор (airflow) для автоматического переобучения
- хранилище артефактов (mlflow) для отслеживания экспериментов
- api для сервинга модели (fastapi)
- инфраструктура как код (terraform для yandex cloud)
- ci/cd пайплайн для автоматической выкатки модели (github actions)
- мониторинг качества модели

**что не входит:**
- разработка фронтенда для маркетологов
- интеграция с crm-системой заказчика
- a/b тестирование модели

**уровень зрелости ml-системы: 2**
- версионирование кода: git/github
- ci/cd пайплайн выкатки модели на прод: github actions
- хранилище признаков: mlflow model registry
- сервинг модели через api: fastapi на serverless containers
- мониторинг качества предсказаний: grafana дашборды
- система управления экспериментами: mlflow
- оркестратор: airflow

## 5. осуществимость

задача выполнима. данные доступны (биллинг, звонки в поддержку, жалобы).
для mvp достаточно открытого датасета telco customer churn.
ресурсы: 1 ml-инженер, облачная инфраструктура yandex cloud, 2 недели до mvp.

## 6. данные

**источники обучающих данных:**
- исторические данные о клиентах: демография, услуги, платежи, контракты
- для прототипа используется открытый датасет telco customer churn (7043 записи)

**источники продакшн-данных:**
- те же источники, обновляемые ежемесячно
- данные поступают батчами через object storage

**процесс разметки:**
- целевая переменная churn: 1 — клиент ушёл в следующем месяце, 0 — остался
- разметка происходит автоматически по факту расторжения договора

## 7. метрики

**приоритет бизнес-метрик:**
1. monthly churn rate — снижение на 5%
2. удержанные клиенты — доля клиентов из списка, не ушедших после промо-акции
3. конверсия промо — доля клиентов, воспользовавшихся предложением

## 8. оценка качества модели

**офлайн-метрики:**
- recall (полнота) — ключевая метрика, важно найти максимум уходящих клиентов
- precision (точность) — дополнительная, чтобы не тратить бюджет на ложные срабатывания
- roc-auc — общее качество разделения классов

**онлайн-метрики:**
- churn recall — доля реально ушедших среди предсказанных
- promo conversion rate — доля воспользовавшихся промо-предложением

## 9. подбор модели

итеративный подход:
1. baseline: логистическая регрессия (простота, интерпретируемость)
2. эксперименты: random forest, xgboost
3. выбрана логистическая регрессия (recall=0.56, precision=0.62, roc-auc=0.83)
   с балансировкой классов (class_weight='balanced')

## 10. инференс

**тип:** батчевый + real-time api
- ежедневно формируется файл с предсказаниями для загрузки в маркетинговую систему
- api для запросов по одному клиенту (для интеграции с веб-интерфейсом)

## 11. обратная связь

**источники:**
- данные о фактическом оттоке за следующий месяц для переразметки
- метрики качества модели в проде (recall, precision)
- время отклика api (latency)

**использование mdd:** да
- принимаем решения на основе статистического сравнения метрик
- порог для замены модели: recall > 0.50
- оформляется в формате adr

## 12. управление проектом

**команда:** 1 ml-инженер

**результаты:**
- работающий пайплайн обучения и переобучения
- api для инференса
- мониторинг и автоматический откат

**сроки:**
- mvp: 2 недели
- полный цикл с автоматизацией: 3 недели
